# Дорожная карта Pi WSL Desktop

Цель — выпустить удобный Windows-клиент для существующего Pi в WSL: проекты, сессии, чат и ресурсы в одном окне.

**Сверено с GitHub 29 октября 2026 года.** M0–M3 приняты и слиты. M4 — выпуск 1.0 — продолжается. UI21 / PR #24 функционально принят владельцем и объединён squash в `main` (`44a39763`); Visual ACCEPT пока не получен. #26 New Chat реализован в открытом Draft PR #30, но ещё не объединён. Версия пакета — `1.0.0-rc.1`; стабильный 1.0.0 не объявлен.

## UI21 — исторические гейты и отложенный Visual ACCEPT

**Визуальный источник уже утверждён владельцем:** Component Library v5, Board и композиция Design Lab, включая `?state=app` и принятую витрину `?state=showcase`. Задача — перенести их в Electron, подключив существующие обработчики и реальные данные Pi/WSL. Новая концепция дизайна и повторный подбор внешнего вида по старым PNG в текущую работу не входят. [Решение владельца](https://github.com/triagmas/pi-wsl-desktop/issues/21#issuecomment-6398531407).

### Что уже реализовано в PR #24

D1 создал изолированный Design Lab и общие компоненты. D2 подключил их к приложению, но Windows-окно на `31f46e2` было [отклонено владельцем](https://github.com/triagmas/pi-wsl-desktop/issues/21#issuecomment-6398267731). D3 выделил общую композицию для Lab и Electron. В C1–C4 выровнены сайдбар и вкладки сессии, экраны ресурсов и настроек, счётчики и клавиатурный фокус. В C5 исправлены заголовок окна, элементы настроек и статус чата.

**Исторический технический результат C5 — `24152a7`.** После него PR #24 прошёл отдельные функциональные исправления и приёмку; итоговый squash merge — `44a39763`. Приведённые ниже старые результаты остаются историческими и не заменяют проверок финального HEAD.

[Отчёт C1–C4](https://github.com/triagmas/pi-wsl-desktop/issues/21#issuecomment-6409194433) фиксирует базу `0a46f38` и результат `0d406f1`: 23 файла, +888/−221 строка. Локально заявлены Vitest 636 PASS / 10 SKIP и Electron E2E 14/14; это результаты отчёта исполнителя, здесь они заново не воспроизводились. Архив сравнений содержит **16 PNG, а не 16 пар**.

После C5 в PR #24 вошли функциональные пакеты: **F1-A** — реальная проверка Windows+WSL на настоящем Electron; **F1-DIAG** — точная диагностика сбоя оценки токенов на malformed fixture; **F1-C** — видимая ошибка генерации вместо пустого пузыря и offline-валидатор структуры сессий; **F2** — каталог моделей и переключатель thinking из установленного Pi без обязательных или заданных по умолчанию моделей; **R02 + R02 r01** — закрытие находок независимого ревью: общий гейт внешнего писателя перед переключением и отправкой, сериализация изменяющих команд, единая редакция секретов в видимых ошибках, семантический вывод инструментов и приём нативной пары записей Pi `model_change` + `thinking_level_change`.

На HEAD `162386f` GitHub подтвердил **CI 3/3 PASS** (документация и безопасность публичного репозитория, Linux typecheck/lint/tests/build/Electron E2E, Windows typecheck/lint/unit+contract/build/installer/packaged smoke). Локальные Windows+WSL **offline**-гейты пройдены без модельных вызовов: реальный Electron с настоящим мостом, повторное подключение, переключение модели, отправка после переключения без ложного `SESSION_CONFLICT`.

### C5: технические исправления завершены, визуальная приёмка открыта

[Исходное задание C5](https://github.com/triagmas/pi-wsl-desktop/issues/21#issuecomment-6410056356), [ограниченная коррекция R02](https://github.com/triagmas/pi-wsl-desktop/issues/21#issuecomment-6416447703) и [финальный отчёт на `24152a7`](https://github.com/triagmas/pi-wsl-desktop/issues/21#issuecomment-6418566860) подтверждают выполненную работу **по отчётам исполнителя**, но не заменяют независимую проверку самих снимков:

- [x] Исправлена сетка TitleBar реального Electron; в C5 отчёте приведены замеры и проверки кнопок окна.
- [x] Сопоставлены Settings и sidebar с утверждённым Design Lab: пять тем, независимая типографика, живая preview-зона и заголовок «Проекты».
- [x] Проверены доступное состояние чата и поле composer без платного запроса; статус «Чат открыт / Закрыть чат» разделён корректным отступом.
- [x] Сопоставлена правая панель при 1586×992 и узком окне: после `24152a7` head/body симметричны (24 px в сетке, 16 px в overlay); collapse/resize сохранены.
- [x] Исполнитель представил сравнительные материалы в отчётах Issue #21 (R02: четыре композита; финал: BEFORE/AFTER + манифесты). Архивы лежат в локальном `F:\_tmp`, не в этом GitHub PR.
- [ ] **Visual ACCEPT владельца** по снимкам реального Windows Electron после C5. Он не получен, и этот документ не объявляет UI принятым.
- [ ] **Отложенные визуальные гейты после функционального merge PR #24**: Visual ACCEPT владельца и Windows DPI 100/125/150/200% как отдельная матрица — **NOT RUN**. Это не отменяет завершённого squash merge UI21 и не подтверждает визуальную приёмку.

На `24152a7` исполнитель сообщил: focused Vitest **17/17 PASS**, TypeScript node/web, lint и build — PASS; полный Vitest/E2E и Windows DPI-матрица **NOT RUN**. Разницу системного DPI 1.5×→1.25× между запусками отдельно раскрыл в отчёте.

**Технический ACCEPT, зелёный CI и браузерные снимки не заменяют Visual ACCEPT реального Windows-приложения.** Утверждение Design Lab сохраняется; проверяется качество его переноса. Настоящие PTY, diff/файлы и метрики нельзя изображать фиктивными рабочими функциями.

## Как поддерживать этот документ

1. **Не отмечать `[x]` только по отчёту исполнителя.** Подтверждением считаются фактическая приёмка, зелёный CI на конкретном SHA и явное решение владельца.
2. **Новый SHA — новая проверка.** Результаты другого коммита не переносятся; CI и гейты проверяются на актуальном HEAD.
3. **Принятая история не удаляется.** Выполненные пункты и результаты проверок сохраняются — в этом файле или в [архиве](docs/history/ROADMAP-archive-0d406f1.md) со ссылкой.
4. **Расхождение с GitHub — `BLOCKED`.** Если текст документа расходится с Issue/PR/CI, статус помечается `BLOCKED` до сверки, а не угадывается.

При изменении состояния обновляйте относящуюся к нему строку или чекбокс и добавляйте ссылку на Issue/PR и подтверждённый результат. Различайте «реализовано в ветке», «проверено», «визуально принято» и «слито».

Подробные журналы тестов и ревью остаются в Issue/PR и отчётах. Инструкции AI-агентам находятся в [AGENTS.md](AGENTS.md) и связанных Skills.

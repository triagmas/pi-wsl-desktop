# Быстрые локальные гейты (`prek`)

`prek` — оркестратор pre-commit хуков (совместим с форматом
`.pre-commit-config.yaml`). Здесь он закрывает быстрые проверки **до** push;
полный набор остаётся в CI и `prek` его не заменяет.

## Установка

```bash
uv tool install prek         # изолированно, без глобального pip
# либо разово, без установки:
uvx prek --version

prek install                 # включить git-хук pre-commit в этом checkout
```

Проверенная версия: **prek 0.5.7** (Node.js ≥ 22 и `npm` должны быть в `PATH`;
хуки используют `language: system`, поэтому ничего не скачивают при запуске).

## Что запускается

`.pre-commit-config.yaml` содержит четыре локальных хука:

| Хук | Что делает | Область |
|---|---|---|
| `eslint` | `npx eslint` по staged `*.ts`/`*.tsx` | только staged файлы |
| `typecheck` | `npm run typecheck` (оба tsconfig) | проект целиком |
| `electron-dist-platform` | сверяет локальную сборку Electron с ОС | при изменении `package.json` |
| `private-content` | ищет приватные пути, ключи и дампы сессий в staged тексте | все staged текстовые файлы |

Ни один хук не переписывает файлы: автоформатирование отсутствует, `entry`
не меняет содержимое.

## Ручной запуск

```bash
prek run --config .pre-commit-config.yaml --all-files     # всё дерево
prek run --config .pre-commit-config.yaml --files src/renderer/App.tsx
prek validate-config .pre-commit-config.yaml              # проверка конфигурации
```

## Реальная семантика staged vs worktree (измерено, не предположение)

Проверено на синтетическом репозитории в `/tmp` (не в рабочем checkout):

| Режим | Что видит хук | Что делает prek с незакоммиченными правками |
|---|---|---|
| `prek run` (без флагов) | **содержимое индекса** (staged) | сохраняет ВСЕ unstaged-изменения в патч `~/.cache/prek/patches/*.patch`, применяет обратно после прогона |
| `prek run --files a b` | **содержимое рабочего дерева** | ничего: ни патча, ни stash |

Измерение: при staged `STAGED-V2` и unstaged `WORKTREE-V2` хук в первом режиме
увидел `STAGED-V2` (и чужой грязный файл — его staged-версию), во втором —
`WORKTREE-V2`. После обоих прогонов рабочие файлы восстановлены побайтово,
`git stash list` остался пустым. Патч-файлы в `~/.cache/prek/patches/` **не
удаляются** — это копия незакоммиченного содержимого на диске.

### Почему `prek install` остаётся BLOCKED в этом checkout

В рабочем дереве владельца 14 незакоммиченных файлов. Bare-режим (и любой
`git commit` с установленным хуком) временно выносит их в патч: если процесс
прервётся (crash, `kill -9`, закрытие терминала), правки останутся только в
`~/.cache/prek/patches/`, а дерево будет содержать staged-версии. Доказать
безопасность такого сценария нельзя, поэтому:
- `prek install` в рабочем checkout **не выполняется** (BLOCKED);
- в CI хуки не вызываются вовсе.

### Безопасные режимы

1. **Явный набор файлов** (рекомендуется): `prek run --files <paths…>` — патч
   `UNSTAGED` не создаётся, правки владельца не трогаются.
2. **Чистое дерево** (`git status --porcelain` пуст) — bare `prek run`
   безопасен, т.к. сохранять нечего.
3. **Прямой вызов скриптов** без prek: `node scripts/check-private-content.mjs
   <paths…>`, `node scripts/check-electron-dist.mjs` — ничего не пишут.

## Быстрое против полного

- **`prek` (секунды):** lint, typecheck, платформа Electron, приватное
  содержимое.
- **CI (минуты):** Linux typecheck/lint/tests/build + Electron E2E; Windows
  typecheck/lint/unit+contract/build/installer/packaged smoke; Repository
  Contract. Эти job'ы `prek` не дублирует.

## Ограничения гейта приватного содержимого

`scripts/check-private-content.mjs` — набор **общих классов**, а не сканер всех
секретов:

- ловит формы: PEM private key, AWS access key id, GitHub token, Slack token,
  ключи вида `sk-…`, литеральные `Bearer`-креденшелы, абсолютные домашние пути
  реального пользователя (`/home/<user>/`, `C:\Users\<user>\`), чувствительные
  имена файлов (`auth.json`, `.env`, `*.pem|p12|pfx|key`);
- **не** делает энтропийный анализ: случайная строка неизвестного формата
  пройдёт;
- **не** смотрит историю git: уже опубликованное правило не отменяет;
- **не** инспектирует бинарные файлы;
- **не** ловит присваивания «`key = "<литерал>"`» — на фикстурах это даёт
  слишком много ложных срабатываний;
- **не** ловит пути смонтированных дисков (`/mnt/<drive>/…`, `X:\…`): репозиторий
  документирует собственный канонический путь, и правило было бы шумным;
- плейсхолдеры фикстур (`u`, `user`, `fake`, `synthetic`, `test`, …) и значения,
  содержащие слова `synthetic/dummy/example/placeholder`, осознанно не считаются
  секретом — настоящий секрет с таким словом пройдёт;
- ошибка чтения и размер больше 4 МиБ — **нарушение** (fail-closed): непрочитанный
  файл нельзя объявить безопасным.

Известные срабатывания на уже опубликованных файлах (проверено прогоном по
`git ls-files`): `tests/unit/redact.test.ts` содержит реальный домашний путь в
строке-примере, `tests/ui/m1Chat.test.tsx` — демонстрационный GitHub-token из
документации. Это не секреты, но гейт их отмечает; `--all-files` поэтому сегодня
не проходит, поддерживаемый режим — явный набор файлов.

## Ограничения

`prek` — только про проверки. Он **не** подтверждает визуальную приёмку и не
заменяет нативный запуск приложения (см. `windows-launch.md`).

produced five provider attempts, because Pi's own retry (`maxRetries: 3`)

[#41](https://github.com/triagmas/pi-wsl-desktop/issues/41). Streaming and

## 6. Known limitations accepted for 1.0.0 (proposed, owner confirms)

1. Partial answer after Stop is not persisted (#41).
2. One error entry per retry attempt instead of a single summary (#41).
3. Closing an active terminal tab asks no confirmation (#40).
4. Chat title clipped in a narrow window with the right overlay (#37).
5. "New chat" during connecting gives no visible feedback (#38).
6. Terminal verified on Ubuntu only, single tab, no WSL-loss scenario.
7. DPI matrix and second monitor not verified.
8. Unsigned installer, no auto-update, no delta packages.
9. Unresolved resource-ops residuals remain as disclosed in #9; writes into Pi
   resources happen only after explicit user confirmation, with backup and
   rollback — the application is not "read-only by construction".

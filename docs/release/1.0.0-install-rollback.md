# Pi WSL Desktop 1.0.0 — install, upgrade, uninstall, rollback

Applies to the Windows installer `PiWSLDesktop-1.0.0-setup.exe` (NSIS, x64).
No step in this document requires editing Pi files, and none of them may be
executed automatically by CI or by an agent: installing into a real Windows
profile is an explicit user action.

**Publication status:** the `1.0.0` installer is built and verified by CI, but
it is **not published** on a GitHub Release yet. Until it is, install only a
build you produced yourself from the repository; the instructions below
describe the behaviour of the published installer.

## Requirements

- Windows 10/11 x64.
- WSL2 with at least one distribution (`wsl --list --verbose`); verified on
  **Ubuntu**.
- Pi Coding Agent installed inside that distribution and working in a shell
  (`pi --version`). The desktop does not install Pi.
- **Node.js 22.19.0 or newer inside that distribution.** The WSL bridge runs on
  the `node` found there; without it the connection fails with
  `NODE_NOT_FOUND`. Pi 1.5.0 requires `node >= 22.19.0` (this package declares
  `>= 22.13.0`, so the stricter Pi bound applies). Check it with
  `node --version`; the app does not enforce a minimum version itself, an
  outdated Node fails when the bridge starts.
- **Python 3 inside that distribution** — only for the terminal dock (PTY).
  Node is for the bridge and chat, Python 3 is for the terminal; missing
  Python 3 does not block chat or Pi.
- No administrator rights: the installer is per-user and asks for no elevation.

## Before you install

1. Use **only** the official source: the GitHub Releases page of this
   repository. Do not take installers from mirrors, chat attachments or
   re-uploads — a checksum handed out next to the executable does not prove who
   built it.
2. Verify the download against the SHA-256 published in that release (see
   “Integrity and authenticity” below).
3. **Save the installer you are upgrading from together with its SHA-256 in
   your own archive folder.** The application does not keep old installers and
   has no update channel; that copy is your only rollback target.
4. Optional but recommended before any upgrade: copy the user data folder

   ```powershell
   Copy-Item "$env:APPDATA\pi-wsl-desktop" "$env:USERPROFILE\pi-desktop-backup" -Recurse
   ```

## Install

1. Run `PiWSLDesktop-1.0.0-setup.exe`.
2. The installer is one-click and per-user: it installs into
   `%LOCALAPPDATA%\Programs\pi-wsl-desktop`, creates a Start Menu entry
   ("Pi WSL Desktop") and does **not** launch the app automatically.
3. **Integrity and authenticity are not the same thing.**

   - *Integrity:* compare the download with the checksum published in the
     release:

     ```powershell
     Get-FileHash .\PiWSLDesktop-1.0.0-setup.exe -Algorithm SHA256
     ```

     A match proves the file is the one the release describes; a mismatch means
     the download is corrupt or substituted — delete it and re-download.
   - *Authenticity:* a SHA-256 value read from the same place as the executable
     proves nothing about who built it (anyone able to replace the file can
     replace the checksum too). Because this installer is **unsigned**, Windows
     cannot tie it to a publisher either. What you can rely on is the official
     GitHub release page and the fact that the artifact was built by the
     repository's CI from a public commit. Compare the hash against that page
     only.
   - Unsigned software stays riskier than signed software, and an unexpected
     warning is information, not a formality: if SmartScreen or your antivirus
     reacts to a build you did not expect, stop instead of dismissing it. The
     warning appears because there is no signature; it is not a routine step
     this product asks you to skip, and this document does not present bypassing
     it as required or automatically safe.
   - If your organization enforces signed software, do not install this build.
     The mitigation is on the project side (a code-signing certificate), not on
     the user side.
4. Start the app from the Start Menu. On first start it finds WSL
   distributions and the Pi installation inside them; the connecting state is
   shown in the sidebar.

Foreign-directory guard: the installer refuses to write into an existing,
non-empty folder that does not carry the Pi WSL Desktop install marker
(`.pi-desktop-install-marker`). A silent `/D=` override into someone else's
folder is therefore rejected, not silently merged.

Silent install (for scripts):

```powershell
.\PiWSLDesktop-1.0.0-setup.exe /S
```

## Upgrade

1. Close the running application (an open app can pin files in the install
   directory).
2. Run the newer installer. It installs over the existing one and rewrites the
   ownership marker. The user data folder is **kept in place**, which is a
   statement about the folder, not about the format inside it.
3. User data lives in `%APPDATA%\pi-wsl-desktop` (window layout, appearance,
   drafts, cached module state). It is not tied to an installer version, but
   newer versions may migrate what they read; **the reverse direction is not
   guaranteed**. A downgrade is a supported *installation* step, not a
   guaranteed data-compatible step — take the backup from “Before you
   install” if you may need to go back.
4. Pi sessions, settings, Skills, extensions and MCP configuration are not
   stored there; they stay in the distribution.
5. There is no auto-update and no differential package in 1.0.0: every upgrade
   is a manual download and install, and nobody keeps the old installer for
   you.

## Uninstall

1. Close the application.
2. Windows Settings → Apps → "Pi WSL Desktop" → Uninstall, or run
   `Uninstall Pi WSL Desktop.exe` from
   `%LOCALAPPDATA%\Programs\pi-wsl-desktop`.
3. The uninstaller is per-user, needs no elevation and fails safe: if the
   install directory has no ownership marker, it quits without deleting
   anything.
4. User data in `%APPDATA%\pi-wsl-desktop` is **kept** by design
   (`deleteAppDataOnUninstall: false`), so a later reinstall starts with the
   same layout and appearance. Delete that folder manually only if you want a
   full reset.
5. Pi sessions, settings, Skills, extensions and MCP configuration in the WSL
   distribution are not touched by uninstall.

## Rollback

Rollback means "go back to a known-good version", in this order:

1. **App version rollback (normal case).** Close the app, run the archived
   previous installer (for example `PiWSLDesktop-1.0.0-rc.1-setup.exe`, which
   you saved yourself) and start the app. The install directory is replaced;
   the user data folder stays as it is. No Pi data is involved.
   *Failure modes to expect:* the older version may not understand state
   written by the newer one (window layout reset, appearance falling back to a
   default, a draft missing) or, rarely, may fail to start. Neither means data
   in Pi was touched — go to step 2.
2. **Data rollback (exact target).** The backup from “Before you install” is a
   copy of `%APPDATA%\pi-wsl-desktop`. To restore it:

   1. close the application (a running app rewrites these files on exit and
      would undo the restore);
   2. stop any leftover `Pi WSL Desktop` / `electron` process in Task Manager;
   3. move the current folder aside instead of deleting it
      (`pi-wsl-desktop.broken`), then copy the backup into place with the
      original name;
   4. start the app and check that the previous layout/appearance is back and
      that Pi projects and sessions are still listed (they come from Pi, not
      from this folder);
   5. if the app still fails, move the folder aside completely and let it
      create a fresh one — this resets window state only. Delete the
      `.broken` copies only after you are satisfied.
   The restore is *best effort*: it works for files the app owns, and it
   cannot repair state that a newer version has already migrated inside the
   same folder unless you kept the pre-upgrade copy.
3. **Full removal.** Uninstall as above, then delete the leftover
   `%APPDATA%\pi-wsl-desktop` folder. This resets window state and appearance;
   Pi data is still untouched.
4. **Pi-side rollback.** If a Resource Manager operation changed a Pi file, use
   the backup that the application created before applying it (Resource
   manager → history/backup of the operation). Do not restore Pi files by hand
   while Pi is running.
5. **WSL is never reset.** No release step requires `wsl --unregister`,
   `wsl --shutdown` or a distribution reinstall. If the bridge reports a dead
   connection, close and reopen the app; `wsl --terminate <distro>` is a user
   decision, not a supported repair step of this product.

## Verifying that Pi data was not touched

Compare a fingerprint of the Pi home before and after a session:

```bash
find ~/.pi -type f -newermt '<timestamp-before-app-start>' | sort
```

Any new or modified file under `~/.pi/agent` must correspond to an action the
user explicitly confirmed in Resource Manager, or to Pi itself (for example a
new session created by your own prompt). Reading projects, sessions and
history never writes.

## Known limitations of the installer

- Unsigned installer: SmartScreen warning is expected; verify SHA-256.
- `oneClick` + `perMachine:false` is fixed to the current user profile. There
  is no per-machine mode and no install-directory page; the `/D=` command-line
  override remains a disclosed platform residual (guarded by the ownership
  marker, but not a supported scenario).
- No auto-update, no delta packages, no repair mode. Recovery path is
  reinstall of the same or a newer installer.

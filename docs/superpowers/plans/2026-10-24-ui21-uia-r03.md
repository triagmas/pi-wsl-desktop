## Goal

Шесть узких пунктов из gate-комментария, каждый с доказательными тестами:

1. **Сразу-чат**: при выборе сессии — рабочая беседа + composer снизу;

2. **«Новый диалог»**: честное реальное создание через Pi RPC

   1440×900 / 1280×800 / 1024×768, DPI 125/150 (попытка + честный отчёт),

5. **Насыщенные фикстуры**: длинные диалоги с markdown, потоковые инструменты,
   scroll bottom, фокус композера и IME, реальные данные Resources/Skills,

## Evidence (round-0, free, без платных prompt; пробы только в `/tmp`)

Проверено источником Pi 1.4.0 + live free-пробами (без платных prompt; сессии
CLI не тронуты, пустые bucket-каталоги удалены):

- `pi --mode rpc --session-id <id> --session-dir <tmp>` — принимает оба
  флага; `get_state` → `sessionId` + `sessionFile` (полный путь на диске);
  graceful EOF → exit 0; **файл НЕ materialize'ится без prompt**:
  `_persist` (session-manager.js:794) пишет только при
  `persist && sessionFile` и `_hasConversation()`.
- Bare spawn `pi --mode rpc` (без `--session`): env
  `PI_CODING_AGENT_SESSION_DIR` обязателен — без него sessionFile уходит в
  bucket по cwd (`~/.pi/agent/sessions/--tmp-uia-r03--/...`).
- RPC-команды на живом клиенте: `new_session` → `{"cancelled": false}` +
  новый sessionFile в `get_state` (`runtimeHost.newSession()` →
  `rebindSession()`, rpc-mode.js); `set_session_name` → success без prompt
  (имя в `get_state.sessionName`; персист до первой записи — проверить
  источником на T3: `set_session_name` → `_appendEntry(session_info)` до

- `--help`/`--version` подтверждают `rpc`-режим; docs:
  `~/.local/lib/node_modules/@earendil-works/pi-coding-agent/docs/rpc-commands.md`.

## Architecture decisions

- **`newSession` — новый метод Bridge** (наш контракт, SPEC §4.1): params
  `{ projectPath?: string }` (cwd проекта, приходящий из bridge-данных
  `listProjects`; валидация: непустой, без NUL, длина; иначе default
  `resourceCwd = env.PI_WS_DESKTOP_AGENT_CWD ?? process.cwd()`), result
  `{ state, session }` — `session` собирает bridge (roots через
  `resolveSessionRoots`, `projectId/projectPath = spawn-cwd`,
  `availability: 'empty'`, `sizeBytes: 0`, `updatedAt: now`,
  `name: 'Новый диалог'`, `version: 1` — provisional-поля помечены
  комментарием; ничего не отображается из provisional-версии).
- **Политика однослотовости**: `newSession` при живом клиенте →
  `RESOURCE_BUSY` (никакого авто-закрытия, как у `open`). Renderer: при
  `chatBusy` — тот же guard-switch-диалог с копией «Создать новый
  диалог?», confirm → `closeChat()` (fail-closed) → create.
- **Materialization-aware lifecycle**: синтезированная запись —
  provisional (`Set<file>` в App). Проявление файла (после первой отправки;
  fake в E2E зеркалит `_persist`) → refetch `listSessions` → замена
  provisional-записи настоящей. Закрытие непроявленного диалога → файл
  отсутствует → `activeSession` очищается (честно: без первой отправки
  сессии нет — как у Pi). Refetch-триггеры: create, переход chat
  `sending→open` (settle), переход `open→closed`.
- **Сразу-чат через отправку**: выбор сессии читает только историю
  (read-only, write-boundary Issue #5 gate 5 сохранён: старт чата — только
  явным `open`-действием; **явная отправка = явное действие** → submit при
  `status==='closed'` → `chat.open(file)` → `chat.send`). «Открыть чат»
  (приглашение), `chat-actions`-абзац и «Пригласить» убираются; чат-строка
  состояния («Чат открыт»/«Закрыть чат») и error-box с «Повторить»
  (concise actionable) остаются.
- **История в одном скролле с чатом**: хук `useHistoryFeed(api, file)`
  (логика HistoryView: PAGE=100, `sinceEntryId` load-more, partial
  diagnostics) → рендер первым блоком в `.chat-entries` ChatPane перед
  live-записями; composer внизу. `HistoryView.tsx` удаляется (единственный
  потребитель — SessionDetail). Один поток записей: история не
  перезагружается, пока чат активен (иначе дубли), сброс — при смене файла.
- **`openSession` + отсутствующий файл материализации не мешает**: send-gate
  (`chatSession.sendPrompt`, statOrThrow) — ENOENT при idle → пропустить
  mtime-базлайн (файла нет → писать некому; Pi создаст его при первой
  записи); после прогоена существующий refresh-базлайна отрабатывает.
- **Проектный breadcrumb**: fixture-cwd `/` (существует везде → spawn-cwd
  безопасен) → label `Проект`; для новых диалогов cwd = реальный
  синтетический каталог, создаваемый launchApp (`${HOME}/projects/Pi
  Desktop`, mkdir) → breadcrumb «Pi Desktop» как в refs. Смена
  fixture-cwd на существующий-в-тесте путь — stretch-шаг T4 (RED-тесты
  m1/app при откате ripple → вернуть `/` и задокументировать в mapping).
